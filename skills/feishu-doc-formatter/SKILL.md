# 飞书文档排版向导

先帮用户选对路径，再排版。不要把“排版”默认理解成加图、卡片和图表。

## 不可突破的边界

- 不删除、概括、改写或补充原文的观点、数据、日期、人名、链接和结论。
- 默认在副本上工作。无法创建可验证副本时，说明会改动原文并等待用户明确同意。
- 不用全文覆盖处理含媒体、附件、表格、评论锚点、画板、嵌入资源或未知块的文档。
- 不把本地草稿、上传请求成功或计划制作的图片说成已写回飞书。
- 不确定的公式、@人、任务、评论锚点、画板、媒体、嵌入表格/Base、同步块和未知块一律原位保留；不要跨越它们做大范围替换。
- `pre` 不是自动跳过的“代码块”，也不能只凭它长得像 ASCII 就拆开。先用全文领域、相邻语境和块内语义三层证据判断；真实代码、命令和等宽资料一律原样保留，确认是导入残留或版面示意时才转成原生结构。

## 路由 1：先检查能否安全操作飞书

在询问风格前，先检查执行器是否具备飞书连接能力。检查分两层，不能把“已登录”误报为“能改这篇文档”。

1. **环境层**：是否发现飞书 MCP、CLI 或等价适配器；它是否已连接，且能以用户身份读取文档和创建副本。
2. **目标层**：拿到用户的文档 URL/token 后，再确认该用户对这篇文档是否真的有读取、复制和块级写入权限。

只做只读 probe，不要用测试写入来验证权限。按结果分流：

| 状态 | 对用户怎么说 | 可以交付什么 |
| --- | --- | --- |
| `unavailable` | 未发现可用飞书连接 | 请用户粘贴正文或导出 Markdown；只做排版方案/可导入稿 |
| `needs_auth` / `needs_scope` | 工具存在，但还未连接或权限不足 | 说明缺少的认证/权限，完成前不读取、不写入 |
| `read_only` | 可以阅读目标文档，但不能复制或写入 | 完整分析后给排版方案；不声称已改文档 |
| `ready` | 可读取、创建副本、块级更新并写后复读 | 进入完整排版流程 |

若适配器是 lark-cli 或其 MCP 包装，按随 Skill 分发的 [formatter integration notes](references/formatter-integration-notes.md) 做只读检查。它必须分别验证“工具/认证状态”和“目标文档访问”，并保留用户对真实写入的确认边界。

## 路由 2：完整阅读后，把选择权交给用户

先完整读取可用输入（飞书文档、用户粘贴的正文或导出文件），建立内容账本：块类型、标题、表格逐格数据、链接、媒体/附件、特殊块和可视关系。先判定全文是**代码主导、非代码，还是混合**：依据标题、章节、受众、任务目标和正文，而非只看一个 `pre`。每个 `pre` 还要登记实际语义、前后相邻块、是否有明确语言、caption 是否为空、是否承载可视关系、是否像导入残留，以及能否完整映射为原生结构。不要只看开头就猜用户需要图表。

若用户已经明确说了“只要基础整理”“做成汇报版”或指定风格，直接采用其选择并简短复述；否则展示以下编号选项。支持按钮的客户端可将它渲染成按钮，纯文本环境保留编号即可。

> 这篇文档我已经读完。你希望它更接近哪种结果？
>
> 1. **基础整理**：把标题、段落、列表、表格和重点整理清楚，保持克制、整齐、好读。
> 2. **展示型排版**：除基础整理外，把原文中真正有价值的数据或关系做成适合汇报、演示或截图的视觉成果。
> 3. **自动推荐**：我按文档用途、关系密度和展示场景自动选择模式与风格，并说明理由。

不要用“华丽”作为承诺；视觉成果必须增加理解，不是给每段套卡片。

### 用户选 1：基础整理

继续请用户选一个基础风格；未选择时按内容自动给出默认，并说明：

| 选项 | 适合内容 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| `清爽易读` | 普通协作文档、说明、纪要 | 稳定标题层级、段落节奏、列表、表格与少量重点 | 不加图表和装饰卡片 |
| `正式规整` | 方案、报告、对外材料 | 统一编号、表头、引用和强调规则 | 不做品牌化视觉或非必要色块 |
| `演读节奏` | 口播、演讲、叙事稿 | 让正文、停顿和画面提示易区分，保住语序 | 不硬画流程、时间线和 KPI 面板 |

基础整理的完成标准是“更好读”，而不是“看起来做过设计”。

### 用户选 2：展示型排版

继续请用户选一个视觉方向；未选择时按内容自动建议一个，但仍保留原文结构和数据：

| 选项 | 风格 | 适合内容 | 主要视觉成果 |
| --- | --- | --- | --- |
| `商业数据` | Swiss Data × Corporate Blue | 经营复盘、数据对比、管理层汇报 | KPI、趋势、排名、差距、决策矩阵 |
| `杂志专题` | Editorial Magazine × Espresso/Sage | 调研、观点、项目总结 | 强标题、核心证据图、编辑式章节焦点 |
| `亲和计划` | Soft Bento × Espresso/Sage | 运营计划、清单、生活方式、小红书截图 | 主次分明的 Bento 版面、日程、步骤和小型关系图 |
| `强观点` | Neo Brutal × Electric | AI、效率工具、方法论、视频演示 | 一个主命题、强对比、直接标注的流程或数据图 |

每张图都必须同时回答：它是否减少读者来回比较的时间？它是否帮助当前的阅读、决策、讲述或拍摄？任一答案是否定，就保留原生结构，不造图。

### 用户选 3：自动推荐

根据全文，而不是篇幅，自动决定模式与风格，并在写入前用一句话说明理由：

- 用户明确要求朴素、文本以顺序和语气推进，或关系密度低 → **基础整理**；口播稿默认 `演读节奏`。
- 文档有可比较的数据、趋势、差距、转化、方案权衡，且目标是汇报/决策 → **展示型 · 商业数据**。
- 文档以观点、调研证据或专题叙述为主，目标是阅读和截图传播 → **展示型 · 杂志专题**。
- 文档是消费、运营或个人创作计划，核心是日程、清单和模块协作 → **展示型 · 亲和计划**。
- 文档是 AI/效率/方法论的强主张，需要视频演示或强停留感 → **展示型 · 强观点**。
- 边界不清时，优先基础整理；不要因为能生成 SVG 就升级为展示型。

## 执行：先保真，再排版

`ready` 状态下，创建并命名副本，例如 `原题｜排版版｜YYYY-MM-DD`，记录初始 revision。对副本完整读取并保存内容、引用 sidecar、块 ID、媒体 token 与位置，形成内容账本。

按章节串行工作；每一批块级写入后重新读取受影响范围：

1. 先修复确认安全的标题层级、段落、列表、任务和表头；标题最多三级。
2. 把确属同组的步骤、任务或行列数据恢复成原生列表、任务或表格，不把叙述性文字拆成碎片列表。
3. 按下方“`pre` 全文语境路由”处理代码块、等宽文字、导入残留和 ASCII 示意图。
4. 只在所选模式允许且确有必要时，加入 Callout、强调或视觉成果。
5. 展示型的图表/流程/矩阵必须紧邻其来源，标签、数值、单位和方向都能回指内容账本；原表格和正文必须保留。

不要使用一次长输出重写全文。涉及复杂结构时，先插入已验证的新块，再核验，最后才删除对应旧块。任何会令旧 block ID 失效的操作后，重新读取并获取新 ID。

### `pre` 全文语境路由

先做分类，后做任何转换。全文领域只提供默认倾向，**不能单独推翻块内证据**：非代码文档里也可能有真实代码；代码主导文档里即使出现 ASCII，也默认保留，除非相邻正文明确它是版面/流程示意或 Markdown 导入残留。

| 证据组合 | 分类 | 动作 |
| --- | --- | --- |
| 代码主导文档，且 `pre` 是程序、配置、命令、终端输出或技术示例 | 真实代码/等宽资料 | 原样保留；不因排版需要拆开、转表格或转图片 |
| 非代码文档，但 `pre` 有可执行语法、配置片段、命令或正文明确称为代码示例 | 真实代码/等宽资料 | 原样保留；文档领域不能覆盖这项证据 |
| 非代码文档，且 `pre` 是 Markdown 标题/列表/表格/引用残留，或 ASCII 网格、箭头、版面线框；相邻正文说明它承载内容结构而非运行/复制 | 导入排版残留/ASCII 示意 | 能完整映射时转为飞书原生标题、列表、表格、引用或结构块 |
| 代码主导或混合文档中的 ASCII/Markdown 块，但没有明确的版面或导入残留证据 | 证据冲突/未知 | 原位保留并在验收中报告；不得凭猜测转换 |

真实代码、配置、命令和终端输出不可转换。“真实代码”的强证据包括可执行的语言结构、配置键值语义、可复制执行的命令，或相邻正文明确说明用途。不要把单纯的缩进、等宽字体、`+---+` 边框或 Markdown 符号当作代码证据。反过来，不能仅因为文档是非技术主题，就把 JSON、SQL、Shell、提示词模板或公式类片段拆开。

| `pre` 实际内容 | 基础整理 | 展示型排版 |
| --- | --- | --- |
| 真代码 | 原样保留；只有原文或上下文能明确语言时才设置 `lang` | 原样保留，不为“做设计”加图 |
| 终端输出、对齐文字、命令示例 | 原样保留 | 原样保留 |
| 可完整映射的 Markdown 导入残留（标题、列表、表格、引用） | **必须**还原成对应飞书原生块；先插入并核验顺序、层级、链接和表格逐格数据，再删除旧 `pre` | 先完成基础转换；展示只可建立在已还原的原生结构上 |
| 可完整映射的 ASCII 流程、版面线框、架构/关系示意 | **必须**转成原生表格或结构块；保留每个标签、单元格分组、顺序、比例/百分比与相邻说明。先插入并核验新结构，再删除旧 `pre` | 先完成基础转换；只有通过视觉增益测试时，才在同一位置附近新增 SVG、画板、流程或线框图 |
| 无法完整映射的 ASCII 示意 | 原 `pre` 保留；如接口支持且不改正文，可清除无意义空 caption；报告移动端折行风险 | 原 `pre` 保留；只有通过视觉增益测试时，才在同一位置附近新增可读图解 |
| 无法判断 | 原位保留并报告 | 原位保留，不猜测、不转图 |

#### 固定画布线框必须转成版面规格表

`750×750`、`1080×1440` 等固定画布的 ASCII 线框，只要能读出区块名、上下/左右关系、嵌套关系和比例（例如“顶 12% / 中 55% / 左右二分”），就是**可完整映射**，基础整理必须转；不得以“飞书表格不能复刻像素布局”“原文已经规整”或“零改动更克制”为理由保留 `pre`。

在原 `pre` 位置插入一张原生**版面规格表**，至少包含：`区块路径`（如“中部 / 左 / 上”）、`占比或尺寸`、`位置与关系`（全宽、左右并列、上下堆叠等）、`元素/文案`。嵌套框拆成多行路径，水平/垂直分区写入“位置与关系”；比例按原文原样写入。先逐项勾对每个框和标注，再删除旧 `pre`。基础整理不要求、也不得假装复刻像素级画面；保留这份可读的布局规格就是完整映射。

只有区块标签、比例或嵌套关系本身无法读出，且相邻正文也不能补足时，才可保留原 `pre`；验收报告必须点明缺失的是哪一项。对已确认可映射的固定画布线框，验收时应确认对应 `pre` 数量为零，并核对版面规格表的行数和字段。

“完整映射”要求新结构能逐项回指原线框或 Markdown 残留的文字、链接、层级和布局关系；丢掉任何标签、格子、顺序、比例或链接，就不允许删除原 `pre`。这类转换保留的是设计规格或 Markdown 语义，不必保留 Unicode 边框字符。不要为 ASCII 示意图猜测或补 `lang`。展示型新增的是“第二种表达”，不是把原设计规格删掉换成图片；只支持文末媒体插入的适配器也不能声称完成了该转换。

### 媒体、特殊块与失败恢复

- 先登记图片、附件和画板的 token、类型、顺序、尺寸/说明和相邻锚点；需要看内容时只读预览或下载。
- 新视觉优先独立 SVG；避免脚本、远程字体、外部资源和 `foreignObject`。接口不收 SVG 时转换为 PNG/WebP，并保留来源数据表。
- 只支持文末插入的接口不能冒充“插到指定章节”；应使用锚点插入能力或明确降级。
- `partial_success`、警告、更新数量不符、读取失败或 revision 异常都视为未完成：立即停止、重新读取、对照账本定位差异。不要静默全文重写、删除可疑块或自动回滚历史版本。

## 验收与回访

重新读取副本文档，而不是读取缓存或本地稿，逐项核对文字顺序、数字、日期、链接、表格逐格数据、媒体/附件/特殊块 token 与相对位置，以及新图表的来源数据。对每个保留的 `pre` 核对数量、顺序、正文、全文领域判断、块内分类证据与 caption 状态；每个已转换 ASCII 网格或 Markdown 残留逐项核对新原生结构的标签、分组、层级、顺序、比例和链接，确认没有语义遗漏；固定画布线框还要核对原 `pre` 已删除、版面规格表的区块路径/比例/位置关系/元素四列齐全；新增视觉时，再核对其是否紧邻对应结构。

如果用户在本次**手动选择**了基础整理或展示型排版，交付后追加一次简短回访：

> 这次按「<模式> · <风格>」完成。你满意吗？
>
> 1. 满意，之后继续按这个偏好处理
> 2. 想微调这次的模式或风格
> 3. 下次改用自动推荐

只有用户明确选 1 或 3，且当前产品支持跨会话偏好，才保存该偏好；否则只在当前会话使用，不能承诺“下次会记得”。自动推荐路径不强制再问这道题。

最终只报告：副本文档链接、连接状态、选择的模式/风格及理由、实际结构/视觉变更、内容验收结果、未完成项及原因。执行器契约见 [references/operation-contract.md](references/operation-contract.md)。
